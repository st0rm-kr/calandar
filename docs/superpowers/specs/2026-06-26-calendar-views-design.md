# 首页日历视图切换设计 Spec

- **状态**: 已确认设计，待用户评审 spec
- **日期**: 2026-06-26
- **作者**: 产品 + 工程协作（brainstorming 产出）
- **范围**: 首页 Calendar 卡片右上角控件从来源筛选改为视图切换；订阅来源仍由左侧“我订阅的”控制。

---

## 1. 背景

当前首页 Calendar 卡片右上角的 `全部 / 我的群 / 好友` 原本承担来源筛选作用。引入“我订阅的”订阅源列表后，来源筛选职责已经迁移到左侧订阅列表，右上角继续保留这些按钮会造成语义重复：

- 用户已经可以通过订阅源勾选 `自身日程 / 自身活动 / 好友日程 / 群组活动`。
- `全部 / 我的群 / 好友` 与订阅源选择有交叉，且粒度更粗。
- 右上角位置更适合承载“当前日历用什么方式看”的切换。

目标是让控件职责清晰：左侧控制“看哪些来源”，右上角控制“用什么视图看”。

---

## 2. 目标

1. 将右上角 `全部 / 我的群 / 好友` 改为 `月视图 / 周视图 / 列表 / 空闲`。
2. 保留当前月视图作为默认视图。
3. 复用现有 `/api/calendar?...&sources=...` 数据，不新增后端接口作为第一版要求。
4. 保持 Feed 的角色：展示选中日期或当前视图相关的时间流详情。
5. 保持隐私边界：好友 `busy_only` 只能显示忙碌块，不展示标题和地点。

---

## 3. 非目标

- 不在第一版实现复杂推荐算法。
- 不新增周期日程、地点地图、冲突分析面板。
- 不把订阅源选择同步到 URL。
- 不移除左侧“我订阅的”。
- 不改活动、日程、好友、群组的数据模型。

---

## 4. 视图定义

### 4.1 月视图

默认视图。保留现有月历格子：

- 每个日期格展示日期、当天项目数量和颜色点。
- 点击日期后，下方 Feed 展示当天的竖向时间轴。
- 顶部 `上一个 / 下一个` 导航按月移动。

适用场景：快速看整月哪几天有安排、哪几天比较忙。

### 4.2 周视图

新增 7 天时间表：

- 横向为一周 7 天。
- 纵向为小时刻度，建议覆盖 `07:00-24:00`，凌晨项目可折叠到“其他时间”。
- 日程/活动以块状卡片落在对应日期和时间段。
- 点击块后，下方 Feed 展开对应日期并聚焦该项目。
- 顶部 `上一个 / 下一个` 导航按周移动。

适用场景：判断这周哪天晚上适合约活动。

### 4.3 列表视图

新增 Agenda 列表：

- 按时间升序展示当前窗口内的日程和活动。
- 按自然日期分组：今天、明天、本周末、下周、之后。
- 每项展示时间、标题、来源标签、参与人数或可见性。
- 点击条目后，下方 Feed 展开对应日期并聚焦该项目。
- 顶部 `上一个 / 下一个` 导航按列表窗口移动，第一版窗口为 14 天。

适用场景：快速扫“接下来有什么”，不需要理解日历格子。

### 4.4 空闲视图

新增 Hangout 特色视图：

- 以 7 天为窗口展示每天的忙碌块和可约窗口。
- 自身日程、活动、好友日程、群组活动都转化为 busy block。
- 好友 `busy_only` 显示为“忙碌”，不展示标题和地点。
- 对于没有 busy block 的时间段，展示可约窗口，例如 `今晚 19:00-21:00 可约`。
- 第一版只做本地计算，不给“最佳推荐”排序打分。
- 顶部 `上一个 / 下一个` 导航按周移动。

适用场景：用户想发起 Hangout 前，先找大家相对空的时间段。

---

## 5. 信息架构

首页 Calendar 区域分为三层：

1. 左侧订阅源：控制数据来源。
2. 右上角视图切换：控制渲染方式。
3. 主内容区域：根据当前视图渲染月历、周表、列表或空闲窗口。

Feed 保留在 Calendar 下方：

- 月视图：Feed 展示选中日期。
- 周视图：Feed 展示点击的日期或当前周内最近有安排的日期。
- 列表视图：Feed 展示点击条目所在日期。
- 空闲视图：Feed 展示点击空闲窗口所在日期，并提供创建 Hangout 的上下文入口。

---

## 6. 状态与 URL

新增前端状态：

```ts
type CalendarView = 'month' | 'week' | 'list' | 'availability'
```

URL query 同步当前视图：

```text
/?view=month
/?view=week
/?view=list
/?view=availability
```

规则：

- 无 `view` 时默认为 `month`。
- 非法 `view` 回退到 `month`。
- 切换视图时更新 URL query，不丢失登录态或现有页面状态。
- 第一版订阅源选择继续保留在前端 state，不进入 URL。

---

## 7. 数据流

沿用现有日历请求：

```text
GET /api/calendar?from=...&to=...&filter=all&sources=...
```

前端根据视图决定 `from/to`：

- 月视图：当前月网格范围 + Feed 时间轴范围。
- 周视图：当前周起止。
- 列表视图：当前起点后 14 天。
- 空闲视图：当前周起止。

渲染层对同一组 `CalendarItem[]` 做派生：

- 月视图：按 `yyyy-MM-dd` 聚合。
- 周视图：按日期和小时定位。
- 列表视图：按时间排序并按自然日期分组。
- 空闲视图：把 item 转换成 busy block，再从默认可约时段中扣除 busy block。

---

## 8. 隐私与权限

必须沿用后端已返回的脱敏结果，不在前端尝试还原隐私信息：

- 好友 `busy_only`：标题显示“忙碌”，地点为空。
- 好友 `private`：后端不返回。
- 群活动：只返回用户所在群组的活动。

空闲视图只能展示“忙碌 / 可约”，不应通过视觉或文案暗示好友的具体私人安排。

---

## 9. 交互细节

- 视图切换按钮使用明确文本，不使用纯图标。
- 当前视图按钮需要有可见选中态和 `aria-pressed`。
- 键盘用户可以 Tab 到每个视图按钮并切换。
- 颜色只能作为辅助信息，项目仍需显示来源标签或类型文本。
- 空状态按视图定制：
  - 月视图：这段时间还没有安排。
  - 周视图：这周暂无安排。
  - 列表视图：接下来两周暂无安排。
  - 空闲视图：没有可计算的忙碌块，可直接发起 Hangout。

---

## 10. 实施边界

第一版以 `CalendarPage.tsx` 内部实现为主，必要时拆出小组件：

- `CalendarViewSwitcher`
- `MonthView`
- `WeekView`
- `AgendaView`
- `AvailabilityView`

不要求修改数据库和后端服务。现有 `/api/calendar` 已能返回 source metadata 和脱敏后的 items。

---

## 11. 测试策略

前端测试覆盖：

1. 默认进入首页时显示月视图。
2. 右上角视图按钮为 `月视图 / 周视图 / 列表 / 空闲`，不再显示 `全部 / 我的群 / 好友`。
3. 切换周视图后展示 7 天结构和小时刻度。
4. 切换列表视图后按日期分组展示项目。
5. 切换空闲视图后显示 busy block 和可约窗口。
6. `?view=week|list|availability` 可直接进入对应视图。
7. 非法 view 回退到月视图。

验证命令：

```bash
cd apps/web
npm test
npm run lint
npm run build
```

后端不新增接口时无需新增 Go 测试；如果实施中发现必须调整 `/api/calendar` 查询窗口或返回字段，则补充对应 Go 测试。

---

## 12. 自检

- 没有新增后端接口依赖。
- 没有改变订阅源职责。
- 没有要求读取好友 private 日程。
- 没有把颜色作为唯一状态表达。
- 没有把日视图作为顶层视图，避免与 Feed 重复。
