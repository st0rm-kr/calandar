# 公开群发现、群分享页与匿名协作设计 Spec

- **状态**: 已确认设计，待用户评审 spec
- **日期**: 2026-06-26
- **作者**: 产品 + 工程协作（brainstorming 产出）
- **范围**: 新增公开群发现、本地订阅、公开群日历页和匿名协作能力；匿名用户可在授权前提下浏览、订阅、加入群活动，并在允许时创建新的群活动，但不进入正式群成员体系。

---

## 1. 背景

当前匿名能力主要停留在单活动详情只读：

- `/e/:slug` 支持匿名查看活动详情
- 真正报名仍要求登录
- 群活动仍然主要服务于正式账号和正式群成员

这和你现在要的目标有明显差距。你要的其实是一个“轻量公开协作层”：

1. 未登录用户进入首页，也能直接搜索公开群
2. 未登录用户可以把公开群本地订阅到首页
3. 未登录用户可以进入某个公开群的群日历页
4. 未登录用户可以加入该群里的具体活动
5. 在群主允许时，未登录用户还可以创建新的群活动
6. 但这些匿名用户始终不是正式群成员

所以这次设计不再只是“群分享页增强”，而是：

- 公开群发现
- 首页本地订阅
- 公开群日历页
- 匿名轻身份协作

---

## 2. 核心判断

### 2.1 不做两套独立业务系统

产品入口会分流成：

- 已登录用户的完整体系
- 未登录用户的轻量协作体系

但技术上不建议做两套完全独立的活动系统。推荐保持：

- **一套群活动与群日历模型**
- **两类 actor**
  - `member user`：正式登录用户，具备群内身份
  - `guest collaborator`：未登录或不以正式群成员身份参与的轻身份协作者

这样可以最大程度复用现有活动、日历、群治理逻辑。

### 2.2 匿名用户永远不是群成员

匿名协作者：

- 不进入 `group_members`
- 不拥有正式成员权限
- 不可见成员列表
- 只在公开群和公开群活动上具备“浏览、加入、在允许时创建/编辑自己内容”的能力

这点是明确边界，不能含糊。

### 2.3 公开群不等于完全开放

“公开”只意味着：

- 可被搜索
- 可被匿名本地订阅
- 可被匿名浏览

匿名是否能加入活动、是否能创建活动，仍然是独立权限开关，由群主决定。

### 2.4 本地订阅不是账号体系

匿名用户的“订阅群日历”定义为：

- 只存在当前浏览器
- 不要求登录
- 不跨设备同步
- 本质更像收藏/关注

它不产生正式账号关系，也不产生正式群成员关系。

### 2.5 匿名创建直接进入群日历

匿名创建的群活动：

- 创建成功后立即写入活动表
- 立即显示在群公开日历里
- 不经过审核流

这是本次设计明确确认的产品决策。

## 3. 目标

1. 匿名首页可以搜索公开群并进行本地订阅。
2. 匿名首页可以聚合显示本地订阅的公开群日历。
3. 每个公开群都有一个公开群日历页。
4. 匿名用户可以加入公开群里的具体活动。
5. 在允许时，匿名用户可以创建新的群活动。
6. 群主/已登录管理者始终拥有兜底管理能力。

---

## 4. 非目标

- 不允许匿名用户创建个人日程
- 不允许匿名用户成为正式群成员
- 不实现匿名订阅跨设备同步
- 不实现匿名身份升级或账号合并
- 不做公开群内容广场
- 不向匿名用户开放成员列表、好友关系、私密日程

---

## 5. 用户角色

### 5.1 群主 / 已登录管理者

能力：

- 设置群是否公开
- 设置匿名是否可加入活动
- 设置匿名是否可创建活动
- 分享公开群页面
- 管理群内所有活动，包括匿名创建的活动

### 5.2 正式群成员

已登录且属于该群。

能力：

- 正常加入、创建、编辑、删除群活动
- 通过公开群页访问时仍按正式身份处理

### 5.3 访客型已登录用户

已登录但不是该群成员。

能力：

- 可以浏览公开群
- 若群允许匿名协作，可以以 guest 协作者身份继续参与
- 不自动获得正式成员权限

### 5.4 匿名协作者

未登录用户，或选择不以正式成员身份参与的浏览者。

能力：

- 搜索公开群
- 本地订阅公开群
- 浏览公开群日历
- 在允许时加入活动
- 在允许时创建群活动
- 编辑/删除自己匿名创建的活动

限制：

- 不能创建个人日程
- 不能查看成员列表
- 不能成为群成员
- 不能管理别人创建的匿名活动

## 6. 关键设计决策

| # | 议题 | 决策 |
|---|------|------|
| D1 | 首页匿名态 | 未登录首页提供公开群搜索与本地订阅，不只是登录入口 |
| D2 | 群可见性 | 群可设置 `public / private` |
| D3 | 公开页路由 | 新增公开群页 `/pg/:public_slug` |
| D4 | 本地订阅 | 匿名订阅仅保存在当前浏览器 |
| D5 | 匿名加入 | 匿名用户可加入具体群活动，但不是群成员 |
| D6 | 匿名创建 | 仅限群活动，不允许匿名创建个人日程 |
| D7 | 权限来源 | 公开、匿名加入、匿名创建是三个独立权限维度 |
| D8 | 管理权 | **双重管理**：匿名创建者可管理自己内容；群主/已登录管理者始终可兜底管理 |
| D9 | 审核 | 匿名创建成功后直接进入群日历，无审核 |
| D10 | 公开页视图 | 第一版提供 `月历` 和 `列表` |

## 7. 群设置模型

在现有群模型上新增三类公开协作设置。

### 7.1 群可见性

- `visibility = private`
  - 不可被匿名搜索
  - 不可被匿名订阅
  - 没有公开群页

- `visibility = public`
  - 可被匿名搜索
  - 可被匿名本地订阅
  - 可被匿名浏览公开群页

### 7.2 匿名加入开关

- `allow_anonymous_join = true | false`

说明：

- 群公开不等于默认允许匿名加入
- 该权限由群主单独决定

### 7.3 匿名创建开关

- `allow_anonymous_create = true | false`

说明：

- 只影响“创建群活动”
- 不影响个人日程

### 7.4 分享动作

“分享群活动/分享群日历”在第一版只是一个 UI 入口，用来：

- 复制当前群的公开链接
- 顺手调整该群的公开协作设置

最终分享出去的是公开群页地址，而不是单独一套“按链接权限”模型。

这样首页发现、公开页访问和群内分享的权限语义保持一致，不会因为多个分享链接出现冲突权限。

## 8. 路由与页面

### 8.1 匿名首页 `/`

未登录用户进入 `/` 时，不强制跳登录，而是进入公开群发现页。

页面模块：

1. 公开群搜索框
2. 我本地订阅的群
3. 我订阅的公开群聚合日历
4. CTA：查看某个群的公开日历

限制：

- 不提供匿名“创建个人日程”
- 不提供正式成员入口

### 8.2 公开群页 `/pg/:public_slug`

这是公开群的专属群日历页。

页面内容：

- 群名
- 群简介
- 权限提示：
  - 是否允许匿名加入活动
  - 是否允许匿名创建活动
- 视图切换：
  - 月历
  - 列表
- 活动详情区

若 `allow_anonymous_create = true`，展示 `创建群活动`。
若 `allow_anonymous_join = true`，在活动详情里展示 `加入活动`。

### 8.3 公开群页与分享关系

分享动作复制的是稳定公开地址：

```text
/pg/:public_slug
```

必要时可加活动高亮 query：

```text
/pg/:public_slug?event=123
```

## 9. 信息架构

### 9.1 匿名首页

匿名首页分三层：

1. 公开群搜索
2. 我本地订阅的公开群
3. 聚合日历视图

这意味着匿名用户不必先拿到某个分享链接，才能开始使用产品。

### 9.2 公开群页

公开群页分四层：

1. 顶部 Hero：群信息 + 权限说明
2. 视图切换：月历 / 列表
3. 主视图区：专属于这个群的群活动日历
4. 活动详情 / 创建入口

## 10. 核心流程

### 10.1 群主公开一个群

1. 群主进入群详情页
2. 打开公开协作设置
3. 选择：
   - 是否公开
   - 是否允许匿名加入活动
   - 是否允许匿名创建活动
4. 系统生成或启用 `public_slug`
5. 群主复制公开群链接

### 10.2 匿名用户从首页发现公开群

1. 打开首页
2. 搜索公开群
3. 查看搜索结果
4. 打开某个公开群
5. 可选择本地订阅

### 10.3 匿名用户本地订阅公开群

1. 在搜索结果或公开群页点击 `订阅`
2. 前端把 `group_id/public_slug` 存入 localStorage
3. 首页聚合日历立即纳入该群

说明：

- 不要求登录
- 不落库
- 换设备不会同步

### 10.4 匿名用户加入活动

前提：

- 该群 `allow_anonymous_join = true`

流程：

1. 打开公开群页
2. 点击某个活动
3. 点击 `加入活动`
4. 若当前浏览器无 guest 身份，先填昵称
5. 创建该群作用域内的 guest session
6. 写入匿名活动参与记录
7. 返回成功提示

### 10.5 匿名用户创建群活动

前提：

- 该群 `allow_anonymous_create = true`

流程：

1. 打开公开群页
2. 点击 `创建群活动`
3. 若无 guest 身份，先填昵称
4. 填写群活动字段：
   - 标题
   - 类型
   - 开始时间
   - 结束时间
   - 地点
   - 人数上限（可选）
5. 创建成功后直接返回公开群页
6. 新活动立即显示在群日历里

### 10.6 匿名用户管理自己创建的活动

前提：

- guest token 与活动创建来源匹配

能力：

- 编辑
- 删除

群主/已登录管理者也始终可以这样做。

## 12. 数据模型

### 12.1 groups 扩展

在现有 `groups` 表上增加：

- `visibility`：`private / public`
- `public_slug`：nullable unique
- `allow_anonymous_join`：boolean
- `allow_anonymous_create`：boolean

设计原因：

- 公开、匿名加入、匿名创建都是群级别能力
- 首页搜索、本地订阅、公开群页都基于稳定的群公开标识

### 12.2 group_guests

新增表，用来表示匿名协作者，**作用域限定在单个群**。

字段建议：

- `id`
- `group_id`
- `nickname`
- `guest_token_hash`
- `created_at`
- `updated_at`
- `last_seen_at`

设计原因：

- 避免创造跨群的“影子匿名账号”
- 匿名身份只对某个群生效，边界清晰

### 12.3 events 扩展

建议扩展活动来源字段：

- `submitted_by_type`：`user / guest`
- `submitted_by_user_id nullable`
- `submitted_by_guest_id nullable`
- `submitted_by_name`

说明：

- 正式用户和匿名用户都可成为活动发起来源
- 群主仍然拥有兜底管理权

### 12.4 event_guest_participants

新增匿名活动参与表，避免破坏现有 `event_participants(user_id uuid)` 结构。

字段建议：

- `id`
- `event_id`
- `guest_id`
- `nickname_snapshot`
- `status`：`joined / left`
- `created_at`
- `updated_at`

说明：

- 第一版做轻量二元参与态即可
- 不强求复用完整 `invited / going / maybe / not_going`

### 12.5 anonymous_home_subscriptions（前端本地）

不建数据库表。

前端 localStorage 保存：

```json
[
  { "group_id": 1, "public_slug": "climbing-club" },
  { "group_id": 2, "public_slug": "weekend-dinner" }
]
```

## 13. API 设计

### 13.1 公开群发现

- `GET /api/public/groups/search?q=`
  - 只返回 `visibility = public` 的群

- `GET /api/public/groups/:public_slug`
  - 返回群公开信息与匿名协作设置

- `GET /api/public/groups/:public_slug/calendar?from=&to=&view=`
  - 返回该群的活动日历数据
  - 不返回成员私密信息

### 13.2 群主设置

- `PATCH /api/groups/:id/public-settings`
  - 更新：
    - `visibility`
    - `allow_anonymous_join`
    - `allow_anonymous_create`

### 13.3 guest session

- `POST /api/public/groups/:public_slug/guest-sessions`
  - 入参：`nickname`
  - 出参：`guest_token`, `guest_profile`

### 13.4 匿名加入活动

- `POST /api/public/groups/:public_slug/events/:event_id/join`
  - Header 携带 `guest_token`
  - 仅当 `allow_anonymous_join = true`

- `POST /api/public/groups/:public_slug/events/:event_id/leave`
  - Header 携带 `guest_token`

### 13.5 匿名创建活动

- `POST /api/public/groups/:public_slug/events`
  - Header 携带 `guest_token`
  - 仅当 `allow_anonymous_create = true`

### 13.6 匿名编辑/删除自己创建的活动

- `PATCH /api/public/groups/:public_slug/events/:event_id`
- `DELETE /api/public/groups/:public_slug/events/:event_id`
  - Header 携带 `guest_token`
  - 仅允许 guest 管理自己提交的活动

## 14. 前端设计

### 14.1 匿名首页

未登录时首页展示：

- 公开群搜索框
- 已订阅公开群列表
- 聚合月历 / 列表视图

不展示：

- 个人日程入口
- 需要正式登录的个人功能

### 14.2 公开群页

页面内容：

- 群名、简介
- 明确权限说明：
  - `允许匿名加入活动`
  - `允许匿名创建活动`
- 视图切换：
  - 月历
  - 列表
- 活动详情
- 条件性 `创建群活动`

### 14.3 昵称收集时机

只在第一次写操作时触发：

- 加入活动
- 创建活动
- 编辑自己活动

纯浏览和本地订阅不要求输入昵称。

### 14.4 状态表达

- 匿名创建的活动要标注来源：`访客发起`
- 正式成员活动可标注：`群成员发起`
- 匿名活动也要支持 `已结束` 表达，与现有日历规则一致

## 15. 风险与防护

### 15.1 滥用与垃圾内容

既然匿名创建后直接进入群日历，就必须提供最基本的治理：

- 群主可随时关闭匿名创建
- 群主可删除任何匿名活动
- 按 IP / guest token 限流
- 群可从 `public` 切回 `private`

### 15.2 身份碎片化

匿名用户清理浏览器或换设备后，会成为新的 guest。第一版接受这个限制。

### 15.3 公开群的边界

公开只意味着可发现与可浏览，不意味着开放所有协作权。权限提示必须在 UI 上说清楚。
