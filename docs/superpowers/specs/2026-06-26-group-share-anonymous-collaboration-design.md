# 群分享页与匿名协作设计 Spec

- **状态**: 已确认设计，待用户评审 spec
- **日期**: 2026-06-26
- **作者**: 产品 + 工程协作（brainstorming 产出）
- **范围**: 新增面向群活动分享的公开群日历页，支持未登录访客以轻身份加入群活动，并在授权时匿名创建和管理群活动。

---

## 1. 背景

当前产品的分享能力主要围绕单活动详情页展开：

- `/e/:slug` 支持匿名只读查看活动详情。
- 真正报名仍要求登录。
- 群活动仍然主要服务于正式账号 + 正式群成员。

这和“把一个群活动/群日历发到微信群里，任何拿到链接的人都能直接协作”的场景还有距离。

本次需求的目标不是把匿名访客变成正式群成员，而是让分享链接本身成为一个轻量协作入口：

1. 未登录用户可直接看某个群的活动日历。
2. 未登录用户可以直接加入群活动。
3. 在已登录分享者允许的前提下，未登录用户还可以匿名创建新的群活动。
4. 匿名创建成功后，活动立即出现在群日历里，不走审核流。

---

## 2. 核心判断

### 2.1 不做“两套独立业务体系”

虽然产品入口会分流成“登录协作”和“匿名协作”两种体验，但技术上不建议做两套完全独立的活动系统。

推荐方案是：

- **一套群活动模型**
- **两类 actor**
  - `member user`：正式登录用户，且具备群内身份
  - `guest collaborator`：未登录或不以正式群成员身份参与的轻身份协作者

这样可以复用现有群活动和日历逻辑，同时把匿名协作限制在分享页场景内。

### 2.2 匿名用户不是群成员

匿名协作者：

- 不进入 `group_members`
- 不拥有正式群成员权限
- 只在群分享页和相关群活动上具备“加入/创建/编辑自己内容”的能力

产品理解是：**分享链接代表分享者对看到链接的人有基本信任，但这种信任不等于正式成员身份。**

### 2.3 匿名创建成功后直接可见

匿名创建的群活动：

- 创建成功后立即写入活动表
- 立即出现在该群分享页的月历/列表中
- 不设审核队列

产品前提是：只要分享者发出了这个链接，就接受“拿到链接的人可以直接参与协作”这一事实。

---

## 3. 目标

1. 新增一个可公开访问的群分享页。
2. 已登录分享者可以控制这个分享页是否允许匿名创建/编辑。
3. 匿名访客不登录也可以加入群活动。
4. 在允许匿名编辑时，匿名访客可以创建新的群活动。
5. 匿名创建者和群主/已登录管理者形成双重管理关系。

---

## 4. 非目标

- 不让匿名用户创建个人日程。
- 不让匿名用户成为正式群成员。
- 不让匿名用户访问群成员列表、好友关系、个人日程。
- 不做审核工作流。
- 不做匿名用户升级/合并到正式账号的复杂迁移流程。

---

## 5. 用户角色

### 5.1 分享者 / 群内管理者

满足以下任一条件：

- 群主
- 当前具备群活动管理权限的已登录正式用户

能力：

- 生成群分享链接
- 选择是否允许匿名编辑
- 查看并管理分享页上的所有群活动
- 关闭匿名编辑或吊销分享链接

### 5.2 正式群成员

已登录且在该群内。

能力：

- 正常创建、加入、取消群活动
- 通过分享页访问时仍按正式身份处理

### 5.3 访客型已登录用户

已登录，但不是该群正式成员。

能力：

- 可以打开分享页
- 若分享页允许匿名协作，则可选择以 `guest collaborator` 身份继续参与
- 不自动获得正式群成员权限

### 5.4 匿名协作者

未登录，或选择不以正式成员身份参与。

能力：

- 看分享页上的群活动日历
- 以昵称加入活动
- 在允许匿名编辑时创建新的群活动
- 编辑/删除自己匿名创建的活动

限制：

- 不能创建个人日程
- 不能查看成员列表
- 不能管理其他匿名用户创建的活动

## 6. 关键设计决策

| # | 议题 | 决策 |
|---|------|------|
| D1 | 分享对象 | 分享的是**群协作页**，不是单活动详情页的简单放大版 |
| D2 | 页面路由 | 新增公开路由 `/gs/:share_slug` |
| D3 | 权限开关 | 分享时可勾选 `allow_anonymous_edit` |
| D4 | 匿名加入 | 通过填写昵称完成，不要求登录 |
| D5 | 匿名创建 | 仅限群活动，不允许创建个人日程 |
| D6 | 匿名身份 | 用 `guest_token` 维持轻身份，不创建正式用户账号 |
| D7 | 管理权 | **双重管理**：匿名创建者可管理自己创建的活动；群主/已登录管理者始终可管理 |
| D8 | 群成员关系 | 匿名协作者**不是**正式群成员 |
| D9 | 审核 | 匿名创建成功后直接进入群日历，无审核 |
| D10 | 视图 | 分享页第一版提供 `月历` 和 `列表`，不强制上周视图 |

## 7. 信息架构

分享页结构：

### 7.1 顶部 Hero

- 群名
- 群简介
- 当前分享链接的协作状态：
  - `仅允许加入`
  - `允许匿名创建与编辑`
- 主 CTA：
  - 若 `allow_anonymous_edit = true`：`创建群活动`
  - 否则：`加入已有活动`

### 7.2 日历视图区

第一版提供两个视图：

- `月历`
- `列表`

理由：

- 月历适合快速看分布
- 列表适合快速找到最近活动
- 周视图密度较高，适合作为后续增强，不适合作为第一版公开协作入口

### 7.3 活动详情面板

点击某一天或某个活动后展示：

- 标题
- 开始/结束时间
- 地点
- 是否已结束
- 已加入人数
- 自己是否已加入（若本地已有 `guest_token`）

### 7.4 昵称弹层

匿名用户第一次执行写操作时弹出：

- 输入昵称
- 创建 guest session
- 后端返回 `guest_token`
- 前端存入 localStorage

后续在同一浏览器中继续沿用该 guest 身份。

## 8. 核心流程

### 8.1 已登录分享者创建分享页

入口：

- 群详情页
- 群活动详情页

操作：

1. 点击 `分享群活动`
2. 选择：
   - `仅允许匿名加入`
   - `允许匿名创建和编辑`
3. 系统生成一个群分享链接
4. 分享链接可复制到微信群或其他渠道

结果：

- 链接指向 `/gs/:share_slug`
- 若从活动详情页发起，可附加 `?event=<event_id>` 让页面默认高亮该活动

### 8.2 匿名用户打开分享页

行为：

- 不要求登录
- 可直接看该群的月历/列表
- 看不到群成员列表和私有资料
- 若页面允许匿名编辑，可看到 `创建群活动`

### 8.3 匿名用户加入活动

流程：

1. 打开某个活动详情
2. 点击 `加入活动`
3. 若无本地 guest 身份，先填写昵称
4. 创建 guest session
5. 写入 guest participant 记录
6. 页面提示加入成功

### 8.4 匿名用户创建群活动

前提：

- 当前分享链接 `allow_anonymous_edit = true`

流程：

1. 点击 `创建群活动`
2. 若无 guest 身份，先填昵称
3. 填写群活动字段：
   - 标题
   - 类型
   - 开始时间
   - 结束时间
   - 地点
   - 人数上限（可选）
4. 创建成功后直接返回分享页
5. 新活动立即显示在月历和列表中

### 8.5 匿名用户管理自己创建的活动

前提：

- guest token 对应这条活动的创建者

可做：

- 编辑
- 删除

群主/已登录管理者也始终拥有这些能力。

## 9. 权限矩阵

| 能力 | 群主/管理者 | 正式群成员 | 访客型已登录用户 | 匿名协作者 |
|------|-------------|------------|------------------|------------|
| 查看群分享页 | 是 | 是 | 是 | 是 |
| 查看群活动日历 | 是 | 是 | 是 | 是 |
| 查看群成员列表 | 是 | 是 | 否 | 否 |
| 加入群活动 | 是 | 是 | 以 guest 身份可加入 | 是 |
| 创建群活动 | 是 | 是 | 仅在 `allow_anonymous_edit=true` 时以 guest 身份创建 | 仅在 `allow_anonymous_edit=true` 时创建 |
| 编辑自己创建的匿名活动 | 是 | 是 | 是（如果其 guest token 匹配） | 是 |
| 编辑其他匿名活动 | 是 | 视原群权限而定 | 否 | 否 |
| 创建个人日程 | 是 | 是 | 否 | 否 |
| 加入正式群成员体系 | 已是成员 | 已是成员 | 否 | 否 |

## 10. 数据模型

### 10.1 group_share_links

新增表，用来表示“某个群的一条公开协作链接”。

字段建议：

- `id`
- `group_id`
- `created_by_user_id`
- `share_slug`
- `allow_anonymous_edit boolean`
- `status`：`active / revoked`
- `created_at`
- `updated_at`

设计原因：

- 分享权限是**按链接**控制，不直接绑死在群本身
- 允许一个群生成多个不同权限的链接
- 支持后续吊销和轮换

### 10.2 group_share_guests

新增表，用来表示匿名协作者。

字段建议：

- `id`
- `share_link_id`
- `nickname`
- `guest_token_hash`
- `created_at`
- `updated_at`
- `last_seen_at`

设计原因：

- 匿名不是“无身份”，而是“轻身份”
- 必须能识别“这个 guest 创建/加入过哪些活动”

### 10.3 events 扩展

不建议把匿名用户塞进现有 `users`。

建议扩展活动来源元信息：

- `submitted_by_type`：`user / guest`
- `submitted_by_user_id nullable`
- `submitted_by_guest_id nullable`
- `submitted_by_name`

同时保留现有 `owner_id` 用于兼容现有管理/查询逻辑。

解释：

- `owner_id` 更偏系统内管理责任
- `submitted_by_*` 表示真正的发起来源
- 匿名创建的活动也能被群主统一管理

### 10.4 event_guest_participants

新增匿名活动参与表，避免破坏现有 `event_participants(user_id uuid)` 结构。

字段建议：

- `id`
- `event_id`
- `guest_id`
- `nickname_snapshot`
- `status`：`joined / left`
- `created_at`
- `updated_at`

说明：

- 匿名协作者先做二元加入态，不复用完整 `invited / going / maybe / not_going`
- 这是轻量入口，不必一开始复制正式 RSVP 体系

## 11. API 设计

### 11.1 已登录分享者

- `POST /api/group-share-links`
  - 入参：`group_id`, `allow_anonymous_edit`
  - 出参：`share_slug`, `share_url`

- `PATCH /api/group-share-links/:id`
  - 更新 `allow_anonymous_edit` 或 `status`

### 11.2 公开分享页读取

- `GET /api/public/groups/:share_slug`
  - 返回群公开信息和分享配置

- `GET /api/public/groups/:share_slug/calendar?from=&to=&view=`
  - 返回公开群活动日历数据
  - 不返回成员私有信息

### 11.3 guest session

- `POST /api/public/groups/:share_slug/guest-sessions`
  - 入参：`nickname`
  - 出参：`guest_token`, `guest_profile`

### 11.4 匿名创建活动

- `POST /api/public/groups/:share_slug/events`
  - Header 携带 `guest_token`
  - 仅当 `allow_anonymous_edit = true`

### 11.5 匿名加入活动

- `POST /api/public/groups/:share_slug/events/:event_id/join`
  - Header 携带 `guest_token`

### 11.6 匿名编辑/删除自己创建的活动

- `PATCH /api/public/groups/:share_slug/events/:event_id`
- `DELETE /api/public/groups/:share_slug/events/:event_id`
  - Header 携带 `guest_token`
  - 仅允许 guest 管理自己提交的活动

## 12. UI 设计要点

- 不使用“登录墙”阻断阅读
- 写操作第一次才要求输入昵称
- 权限开关必须用明确文案，不只靠图标
- 匿名创建能力的存在要有明显提示，例如：
  - `这个分享页允许未登录用户创建群活动`
- 若不允许匿名编辑，也要明确提示：
  - `你可以直接加入活动，但不能新建活动`

状态表达：

- 创建者类型可展示为：
  - `群成员发起`
  - `访客发起`
- 匿名活动也要支持 `已结束` 表达，与现有日历卡片规则一致

## 13. 风险与防护

### 13.1 滥用风险

既然匿名创建后直接可见，就必须提供最基本的治理手段：

- 分享链接可吊销
- 可关闭匿名编辑
- 匿名创建频率按 IP / guest token 限流
- 群主可删除任何匿名活动

### 13.2 重复身份

同一匿名用户换浏览器或清空本地存储后，会被视为新 guest。第一版接受这个限制。

### 13.3 责任归属

匿名创建活动在系统里必须保留来源痕迹：

- 谁创建的（guest id / nickname snapshot）
- 通过哪个 share link 创建

不能只留下一个“群里有人发起”的模糊状态。
